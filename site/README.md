# Docs site

The docs site at <https://odonckers.github.io/domestic-ui/>, the root `README.md`, `llms.txt` and
`llms-full.txt` are all generated by one zero-dependency Node script from the sources that already
document the system: `PRINCIPLES.md`, the header comments in `css/`, the pages in `examples/`, and
a few handwritten files in `site/content/`.

```sh
node site/build.mjs           # build _site/ and write README.md, llms.txt, llms-full.txt
node site/build.mjs --check   # exit 1 if README.md, llms.txt or llms-full.txt are stale
```

## Preview

```sh
node site/build.mjs && node scripts/serve.mjs
```

Then open <http://127.0.0.1:4173/_site/index.html>. `scripts/serve.mjs` does not resolve directory
indexes, which is why every docs link points at a file (`principles/index.html`, never `principles/`).

## How the build works

| File | Does |
| --- | --- |
| `site/build.mjs` | Entry point and CLI. `generate(root)` builds everything in memory; `build({ root, outDir, writeRoot })` writes it; `stale(root)` powers `--check`. |
| `site/lib/discovery.mjs` | Reads the repository into one model: principles, token groups, components, examples, overrides, snippets. |
| `site/lib/css-comments.mjs` | Parses CSS header comments, token group comments in `semantic.css`, and the `@layer` order. |
| `site/lib/markdown.mjs` | A small Markdown to HTML converter (the subset `PRINCIPLES.md` and `site/content/` use). |
| `site/lib/pages.mjs` | Defines every page as blocks of Markdown, or custom HTML plus its Markdown equivalent. |
| `site/lib/templates.mjs` | The HTML page frame (skip link, nav, main, footer) and the Markdown twin. |
| `site/lib/outputs.mjs` | `README.md`, `llms.txt` and `llms-full.txt`. |
| `site/assets/site.css` | Docs layout only, with semantic `--dui-*` tokens and the layout primitives. |

`_site/` is wiped and rebuilt each time. `css/` and `examples/` are copied into it unchanged, so the
docs and the live examples load the real CSS by relative path, at `/_site/` locally and at
`/domestic-ui/` on GitHub Pages. Every HTML page gets a Markdown twin next to it (`tokens/space.md`
beside `tokens/space.html`). Output is deterministic (sorted inputs, no timestamps), so `--check` can
compare bytes.

## Source to page

| Source | Pages |
| --- | --- |
| `site/content/readme-intro.md` | The intro of `index.html`, `README.md` and the `llms.txt` summary |
| `PRINCIPLES.md`, each `## ` section | `principles/<slug>.html`, slug from the heading without its number |
| `PRINCIPLES.md`, text before the first `## ` | `principles/index.html` |
| `css/tokens/semantic.css`, each section comment such as `/* Space */` | `tokens/<group>.html` |
| `css/base/*.css` and `examples/base.html` | `components/base.html` |
| `css/layout/<name>.css` | `components/layout/<name>.html` |
| `css/utilities/<name>.css` | `components/utilities/<name>.html` |
| `css/components/<group>/<name>.css` and `examples/<group>/<name>.html` | `components/<group>/<name>.html`, for `atoms`, `molecules`, `organisms` |
| `examples/*.html`, `examples/*/*.html` | Listed on `examples.html` by their `<title>` |

Relative links in `PRINCIPLES.md` and override bodies are repo-root paths. They are rewritten to the
matching docs page where one exists (`examples/theming.html`, `css/layout/stack.css`, a
`PRINCIPLES.md#heading` anchor), and to `https://github.com/odonckers/domestic-ui/blob/main/<path>`
otherwise.

## Adding a component (M2, M3)

No site change is needed. Add the two files below and run `node site/build.mjs`:

- `css/components/<group>/<name>.css`, with `<group>` one of `atoms`, `molecules`, `organisms`.
- `examples/<group>/<name>.html`, a standalone valid page, joined to the CSS by file name. Optional:
  without it the page says there is no example yet. `examples/<group>/index.html` is a showcase,
  not a component; it is listed on `examples.html` only.

The "Coming in M2" or "Coming in M3" note for that group disappears from `components/index.html`
and `README.md` as soon as the group has one CSS file.

### Header comment fields

The parser reads the comment that opens the CSS file:

```css
/*
 * Atom: button
 *
 * The native button element, styled by type. More prose becomes notes.
 * Sentences that mention WCAG, ARIA, focus, contrast or accessibility
 * become the accessibility notes.
 *
 * API
 *   class="button"
 *   --button-gap   space between icon and label (default: var(--dui-space-xs))
 *
 * Example
 *   <button type="button" class="button">Save</button>
 *
 * https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button
 * https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html
 */
```

| Field | Rule |
| --- | --- |
| Label | An optional first paragraph of one line in the form `Word: text`; skipped. |
| Summary | The first sentence of the first prose paragraph. Plain text: it is also the meta description. |
| Notes | The rest of the prose paragraphs. |
| `API` | A paragraph whose first line is `API`; the indented lines below it, dedented. `API: …` one-liners in any comment are collected too. |
| `Example` | A paragraph whose first line is `Example`; used as the markup only when there is no example page. |
| Accessibility | Prose sentences that mention WCAG, ARIA, APG, focus, contrast, accessibility, screen readers, forced colors or reduced motion. If there are none, the page says so and links the spec list and the accessibility principle. |
| Specs | Every URL in the comment, labelled by host: MDN, WHATWG, WCAG (`/WAI/WCAG22/Understanding/`, `/TR/WCAG…`), APG (`/WAI/ARIA/apg`), W3C (other `w3.org`, `csswg.org`), else Other. |

The title is the file name: `visually-hidden.css` becomes "Visually hidden".

### Front matter overrides

To override what the comment gives, add `site/content/components/<group>/<name>.md`
(`site/content/components/base.md` for base elements):

```md
---
title: Button
summary: One line.
specs:
  - MDN <button>: https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button
---
Markdown body = accessibility notes.
```

Only `key: value` pairs and `- item` lists are parsed. Each key is optional; anything left out falls
back to the header comment. A `specs` entry is `Label: URL`. The body replaces the derived
accessibility notes; its relative links are repo-root paths, rewritten as above.

## Snippet convention

The copy-paste markup on a component page, and the ```` ```html ```` blocks in its Markdown twin
and `llms-full.txt`, come from its example page:

1. If the page has regions between `<!-- dui:snippet -->` and `<!-- /dui:snippet -->`, each region is
   one snippet. Name one with `<!-- dui:snippet name="Primary" -->`; the name becomes a heading.
2. Otherwise the inner content of the page's `<main>` element is the single snippet.

The text is used verbatim, never reformatted. Two things are removed:

- the line break right after the opening marker (or `<main …>`) and the whitespace-only last line
  before the closing marker (or `</main>`);
- the common leading whitespace: the smallest indentation of the non-blank lines is removed from
  every line; whitespace-only lines lose up to that many characters.

So the snippet is always the source slice with that indentation removed line by line.
`tests/docs.spec.js` checks this for every page, along with the HTML and Markdown copies. Code
blocks use a fence longer than any backtick run inside the snippet.

```html
<main>
  <h1>Button</h1>
  <!-- dui:snippet name="Primary" -->
  <button type="submit">Save</button>
  <!-- /dui:snippet -->
</main>
```

## Stale check

`README.md`, `llms.txt` and `llms-full.txt` are committed. Edit their sources, never the files
themselves, then run `node site/build.mjs`. Two checks catch a forgotten rebuild:

- `npm test` runs `tests/docs.spec.js`, which compares freshly generated content with the committed
  files byte for byte.
- The Pages workflow runs `node site/build.mjs --check` before building.

## Accessibility of the docs

Every page has a skip link (the first focusable element), a labelled Docs nav with `aria-current`,
one `h1`, tables with `<caption>` and `th scope`, and iframes with a `title`. Code blocks wrap instead
of scrolling horizontally, so no `<pre>` needs `tabindex` or an accessible name (which ARIA 1.2
prohibits on the `pre` element's generic role). `tests/docs.spec.js` runs html-validate and axe (WCAG
2.2 AA tags, light and dark, Chromium) on every page, checks reflow at 320 CSS pixels, and blocks
external requests.
